# Q-058: Tenant isolation, the assumptions and proposals in ADR-0002

**Question.** ADR-0002 v3 rests on five labelled assumptions (AS-1 to AS-5) and two proposals (PR-1,
PR-2). Does each hold, as its owner sees it?

**Why it matters.** ADR-0002 is Tier 1. Its placement choice depends on AS-1, its guarantee on AS-2,
and two of its invariants (I-7, I-8) wait on PR-1 and PR-2.

**Answers so far** (governance owner, 2026-10-29, as security owner and on product points pending the
product owner), quoted as given:

- **AS-2** (Row-Level Security is acceptable isolation for a shared database): "row-level security is
  ok." Answered, security owner.
- **PR-1** (a client's administrator can see a firm's membership in the client's tenant and remove
  it): "client's admin can see their firm data. Would there be any security concerns?"
  - Read as: the client's administrator can see which firm, and which of its users, hold access to
    the client's tenant. Whether the client's administrator can also remove that access is not
    answered.
  - The orchestrator's reply on the security points is in the session of 2026-10-29. Open: removal,
    and what the client sees of the firm's users (security owner, with product owner).
- **PR-2** (Tiqri as operator holds no standing access to tenant data): "If Tiqri Accounting Owner
  handles the books of their client, he/she should be able to manage the accounting data."
  - This answers a different case from PR-2. Tiqri as a firm keeping a client's books works through a
    membership in the client's tenant (ADR-0002 I-7), with the client's roles, audited under the
    user's own identity. That is consistent with Q-031 v3 reading (a).
  - PR-2 is about Tiqri as operator of the platform (support, engineering, database administration)
    reaching a tenant's data without a membership. Still open (security owner, Q-056, SEC-2).
- **AS-1** (many tenants are small and mostly idle): "Tenant (One tenant with multiple clients) can have
  a single database with row-level security at client level (Each client is an organization?)"
  - On the orchestrator's reading: yes, under Q-031 v3 each client organisation is its own tenant, so
    "row-level security at client level" is row-level security at tenant level. A firm's client tenants
    can sit together in one shared database under ADR-0002's placement model.
  - Open: whether "one tenant with multiple clients" means the firm and its clients form one tenant,
    which would change Q-031 v3 (product owner); whether a firm's client tenants are grouped in one
    database, given that one client may work with more than one firm (tech lead); and the size of
    tenants, which AS-1 asked (product owner, Q-038).
- **AS-3** (a firm needs no query across its clients' data): "Not sure whether firm needs one view
  across all its clients' as each client data should have secured, may be some other metrics might be
  needed."
  - Open. If metrics across clients are wanted, ADR-0002 builds them from per-tenant results, only for
    the clients the firm's user holds a membership in. Owner: product owner.
- **AS-4** (background job identity and audit): not answered. Owner: security owner.
- **AS-5** (the sandbox is refreshed with one tenant's production books): "Yes."
  - Consequence for ADR-0002: a sandbox holding a tenant's real books needs the same isolation,
    residency and access control as production. Who may request a refresh is open (security owner).

**Open.** PR-1 (removal), PR-2 (operator access), AS-1 (tenant model and size), AS-3, AS-4, and the
product owner's confirmation of AS-1, AS-3 and AS-5.
