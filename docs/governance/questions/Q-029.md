# Q-029: How do payroll, depreciation and other sub-ledger postings reach the ledger before their modules exist?

**Version 4** re-bases this question on SRC-007, the V2.2 baseline (DEC-0008). V2.2 replaces V1's
blanket block on manual journals to control accounts with enforcement levels. The levels may make the
conflict smaller, but only depending on three earlier questions (GOV-IMPACT-SRC007 v2, section 6.4).

**Question.** The phasing proposes payroll and fixed assets for release 2. Until then, which route
should payroll and depreciation postings take to the ledger?

**Answer these first.** The options below depend on them:

1. **Q-032:** do the enforcement levels govern, or does the attribute table's blanket block?
2. **Q-033:** what level does the first entity start at? The defaults are set by organisation, and the
   evidence points to Enforced for Tiqri. Leaving Enforced needs approval and is reported on the 2.15.8
   governance panel, which is not yet in release 1 (phasing D-2.15.8).
3. **Q-034:** can a control flag be set later on an account that already has history?

**What SRC-007 says, whatever those answers are.**

- "No user journal is acceptable as a substitute" (SRC-007 p.8, S7-2-c02). Payroll is a row of what
  the system posts "without a manual journal" (p.4, S7-0-c10).
- Depreciation "must be auto-calculated by the system, not by a spreadsheet" (p.90, S7-2.8.3-c01).
- Sub-ledger agreements "are auto-computed by the system continuously and must be nil" (p.114,
  S7-2.12.1-c01). The rows for asset and payroll balances (c05, c06) have nothing to agree to before
  the modules exist.
- At Enforced, "the balance is reproducible from that sub-ledger at any past date" (p.27,
  S7-2.2.1-c57). Activating a module proposes raising the level to Enforced (c63).

**Options.**

- **(A) Interim manual journals until release 2.**
  - If Q-032 settles for the levels and Q-033 gives Advisory, or an approved lowering, the journals
    can post with a reason and appear on an exception report (S7-2.2.1-c56). Neither a change request
    nor interim non-control accounts is needed.
  - Otherwise the V1 position stands: relax the block by a change request, or post to interim
    non-control accounts and move the balances at release 2. The flag cannot change on an account
    with history (S7-2.2.2-c47, c51; Q-034).
  - Either way, an interim journal is not an accepted substitute (S7-2-c02). The agreements cannot run
    for payroll and fixed assets in release 1. History before the level is raised is not reproducible
    from a sub-ledger.
- **(B) Payroll and the fixed-asset core in release 1.** This avoids every point above, and makes
  release 1 larger.
- **(C) Payroll by interface from the payroll system in use today; fixed assets in release 1.**
  - Interface postings are not manual journals, so the enforcement level does not touch them.
  - Open: Q-022 (an external payroll feeding TIQACC); whether interface postings (S7-2.1.6-c15) count
    as sub-ledger postings; and how the payroll agreement works without payroll runs.

**Why it matters.** It sets the size and order of release 1, and whether a control is lowered or
relaxed.

**Open.** Decision by the product owner, with the qualified accountant (control accounts) and the tax
specialist (payroll tax and income tax returns), after Q-032, Q-033 and Q-034.
