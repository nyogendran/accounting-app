# Q-054: Which cloud platform and database does TIQACC run on?

**Question.** Where is TIQACC hosted, and on which database?

**What SRC-007 says.**

- "Cloud-hosted; vendors to quote on-premise as an alternative" (p.6, S7-1-c13).
- "Cloud-hosted, multi-tenant or single-tenant, accessed through a current browser with no local
  installation and no browser plug-in" (p.8, S7-2.1.1-c01).
- "Data residency in each jurisdiction whose law requires it; the vendor states where data and
  backups physically sit" (p.10, S7-2.1.3-c04).

SRC-007 names no cloud provider and no database. No earlier project record chose one.

**Answer so far** (governance owner, as tech lead, 2026-10-28): "data lives in Database (Azure SQL
Database) and are we not going with Azure Cloud?" Read as: Microsoft Azure, with Azure SQL Database
holding the data.

**Not the same as G5.** G5 (DEC-0004, deferred) is what project data may be sent to external AI and
search services while TIQACC is being built. It does not decide where TIQACC's own data is hosted.

**Why it matters.** The platform and database shape the architecture: tenant isolation (Q-031), the
data-residency regions per country (S7-2.1.3-c04, Q-028) and the stack decision.

**Open.**

- The stack ADR at L3 records this choice with its alternatives and consequences, for the tech lead's
  approval at Gate B.
- Which Azure regions hold data and backups for each country in scope, where a law requires
  residency. The owner of statutory data-residency rules is itself open (Q-028).
